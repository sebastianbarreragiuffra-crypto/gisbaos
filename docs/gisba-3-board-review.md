# GISBA OS — PERMANENT 3-BOARD REVIEW SYSTEM

Consulta este documento solo cuando haya que tomar una decisión relevante del website (copy, estructura, CTA, SEO, performance, representación del producto). No lo apliques a cambios menores.

## REGLA FUNDAMENTAL

Estos tres directorios NO existen para aprobar automáticamente las ideas.

Su función es:

- contradecir supuestos;
- identificar riesgos;
- proponer alternativas;
- detectar sobre-diseño;
- detectar falta de diferenciación;
- comparar la visión comercial con la técnica;
- evitar que GISBA se aleje de su core;
- buscar una solución mejor cuando exista.

NO forzar consenso.

Cuando haya desacuerdo: mostrarlo explícitamente.

Una recomendación puede terminar en:

MANTENER · REFINAR · FUSIONAR · REEMPLAZAR · ELIMINAR · NO HACER TODAVÍA

La prioridad general es:

CLARIDAD DEL BUYER → FIDELIDAD AL PRODUCTO → DIFERENCIACIÓN → CONFIANZA → CONVERSIÓN → PERFORMANCE → ESTÉTICA

## DIRECTORIO 1 — GISBA WEB, BRAND & CONVERSION BOARD

**Responsabilidad:** decidir si una agencia entiende qué es GISBA, por qué debería importarle, por qué es diferente y si quiere avanzar hacia una demo.

### Integrantes

**1. GISBA Product Marketing & Brand Director**

Protege: core del producto; positioning; messaging; Brand Guidelines; límites de GISBA.

Debe cuestionar cualquier sección que haga parecer GISBA: CRM; ERP; task manager; inbox; software de WhatsApp; solución genérica.

Pregunta: «¿Esto representa realmente GISBA?»

**2. Chilean Digital Agency Buyer**

Actúa como Founder / CEO / Director de una agencia digital chilena.

Evalúa: si entiende la propuesta rápidamente; si reconoce problemas reales de su agencia; si le parece relevante para Chile; si confiaría; si pediría una demo; qué objeciones tendría.

Debe poder decir: «Esto es bonito, pero no lo compraría.»

**3. International B2B SaaS / Agency Buyer**

Compara GISBA contra el estándar de productos SaaS premium y software para agencias en mercados más maduros.

Evalúa: diferenciación; claridad; sofisticación; credibilidad; expectativa de producto; percepción premium.

Sirve para evitar que GISBA quede limitado visual o comercialmente a un estándar únicamente local.

**4. B2B SaaS Growth & CRO Director**

Evalúa: intención de compra; CTA; recorrido; fricción; densidad; orden; conversiones; objeciones; demostración de valor.

Pregunta: «¿Qué impide que alguien pase de entender a querer una demo?»

**5. Creative / Brand Experience Director**

Evalúa: jerarquía; composición; ritmo; consistencia; percepción premium; claridad visual.

Debe impedir: overdesign; cards innecesarias; exceso de texto; ruido visual; estética SaaS genérica.

**6. Senior Web Product Designer / Frontend Experience Director**

Evalúa simultáneamente: UX; responsive; interacción; implementación realista; desktop; mobile.

Mobile NO es desktop reducido.

## DIRECTORIO 2 — GISBA SEARCH & ACQUISITION BOARD

**Responsabilidad:** contrastar lo que quiere Conversion con lo que realmente funciona para adquisición orgánica y pagada.

### Integrantes

**1. Technical SEO Director**

Revisa: arquitectura; HTML semántico; H1-H3; canonical; robots; sitemap; schema; indexación; internal linking.

**2. Google Ads / Paid Search Director**

Piensa como alguien que está pagando por cada clic.

Pregunta: «Si pago por traer este prospecto, ¿la página responde inmediatamente a su intención?»

Evalúa: relevancia; message match; landing experience; CTA; velocidad; calidad probable del lead.

**3. B2B SaaS Demand Generation Director**

Evalúa la página como parte de un funnel más grande: AD / SEARCH → LANDING → INTERÉS → DEMO → PIPELINE.

Puede cuestionar decisiones que sean bonitas pero no ayuden a adquisición.

**4. Search Intent & Content Strategist**

Distingue: qué debe vivir en Home; qué debería tener página propia; qué busca realmente el usuario; qué información sobra.

Protege una regla: LA HOME NO ES UN CATÁLOGO DE KEYWORDS.

**5. Analytics & Experimentation Lead**

Pregunta: «¿Cómo sabremos si esto funcionó?»

Evalúa: eventos; tracking; CTA; funnel; conversiones; experimentación futura.

Debe evitar cambiar cosas solamente por opiniones cuando ya puedan medirse.

---

## DIRECTORIO 3 — GISBA PRODUCT ENGINEERING & REVENUE BOARD

**Responsabilidad:** contrastar marketing y diseño con software, producto, implementación y proceso de venta.

NO desarrolla el SaaS. Utiliza conocimiento técnico para ayudar a vender el software correctamente.

ANTES DE OPINAR DEBE ENTENDER EL DOSSIER GISBA.

### Integrantes

**1. Senior SaaS Frontend Architect**

Evalúa: performance; arquitectura frontend; responsive; accesibilidad; mantenibilidad; assets; carga; estabilidad.

Puede decir NO a una idea de diseño si el coste técnico/performance no justifica su valor.

**2. B2B SaaS Sales Engineer**

Traduce producto complejo a una conversación comercial.

Pregunta: «¿Entiendo suficiente del software como para querer verlo funcionando?»

Detecta: features sin beneficio; beneficio sin prueba de producto; claims ambiguos; problemas de explicación.

**3. Conversion Product Engineer**

Cruza: PRODUCTO + UX + CONVERSIÓN + IMPLEMENTACIÓN.

Evalúa el recorrido completo. No debe optimizar clicks aislados. Debe optimizar: visitante cualificado → entiende producto → entiende valor → confía → quiere demo.

**4. Web Performance / Technical SEO Lead**

Contradice propuestas que: aumenten peso; dañen CWV; generen CLS; añadan JS innecesario; afecten mobile; retrasen LCP.

**5. SaaS Solutions Consultant / Product Specialist**

Protege el core de GISBA.

CORE: PERFORMANCE + SEÑALES + DECISIONES + COORDINACIÓN + CONTEXTO / TRAZABILIDAD

GISBA PULSE: DETECTA → EXPLICA → RECOMIENDA → DECIDE → REGISTRA

Debe cuestionar cualquier representación del producto que no corresponda al dossier.

Usar este proceso:

```

[opinión]

[opinión]

[MANTENER / REFINAR / FUSIONAR / REEMPLAZAR / ELIMINAR / POSPONER]

[por qué]
```

## REGLA ANTI-CONFORMIDAD

Al menos un directorio debe intentar encontrar una objeción, un riesgo o una alternativa antes de aprobar una propuesta importante.

Esto NO significa inventar problemas. Si después de intentar refutarla sigue siendo la mejor opción: APROBARLA.

## REGLA ANTI-OVERDESIGN

No buscar siempre una solución nueva. También es una conclusión válida: «Lo actual es mejor. No tocar.»

## REGLA DE FREEZE

Una vez que:

- los conflictos relevantes se resolvieron;
- no queda P0;
- producto y buyer están claros;
- responsive funciona;
- la conversión tiene recorrido lógico;

la sección entra en FREEZE. No reabrirla por preferencias subjetivas.

Solo reabrir con: datos; usuarios; demos; leads; conversiones; Search Console; feedback real; problema técnico real.
